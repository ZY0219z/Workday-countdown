## V2.1.0方向一：F11-C可信年度数据自动更新

用户选择年度更新方案A：未来自动检查可信年度数据、自动更新，断网继续正常使用；目标是无需用户每年处理JSON或更新整个EXE。当前仅为计划，尚无实现或验收；不改写Q06在2026-10-13确认的V2.0.0“不联网自动抓取”离线策略。

初步流程（待单独设计，不是既定技术方案）：

1. GitHub Actions定期检查官方发布渠道，发现新年度通知后解析、校验并进入可信核验流程。
2. 仅将经过可靠核验的数据发布为可追溯、版本化的年度数据；未经可靠核验的解析结果不得自动生效。
3. 桌面端在适当时机检查并获取数据，核对来源、版本、完整性和可信度，成功安全更新本地年度数据后刷新依赖结果。
4. 无网络继续使用已有有效本地数据；缺年继续明确估算。下载、校验、保存或切换失败不能损坏旧有效数据，不要求以更新整个EXE代替年度数据维护。

开发前分别评估数据发布渠道及维护责任、官方来源解析与复核、信任/防篡改机制、完整性与版本策略、检查频率/网络行为、失败恢复和维护成本。F11-B是否保留为可选高级功能也在该阶段决定，不能据此承诺手动导入将交付V2.1.0。

## V2.1.0方向二：主窗、迷你窗与整体UI/UX

- 主窗口布局和视觉层级，保持下班倒计时最高优先级。
- 迷你悬浮窗精致化，统一按钮/图标、留白/间距/字体/配色和现有主题表现。
- 桌面缩放与窗口尺寸体验。
- 使用GitHub UI Skills进行只读视觉审查；具体技能与适用性在届时评估，用户确认设计方向后再实施，本轮不安装或运行技能。

坚持轻量工具定位，不增加复杂Dashboard，不发展为企业考勤管理工具，不顺带扩大功能范围。

## 后续授权与验收边界

年度数据更新与UI/UX优化必须拆为独立开发任务，分别设计、测试和验收；本轮不确定具体任务编号、不引入复杂架构或规划大量新功能。这里没有授权创建GitHub Actions、联网请求、自动下载/更新代码或视觉实现。先完成V2.0.0既定发布流程；下一步仅等待用户正式授权D15。
