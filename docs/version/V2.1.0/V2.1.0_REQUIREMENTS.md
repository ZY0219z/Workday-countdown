## 第一阶段：UI 局部改善

依据已完成的 `PRE-V2.1-UI-AUDIT`，用户于 2026-10-22 一次性授权合并实施 UI-01、UI-02、UI-03、UI-05，保留原审查编号。本批实际修改、验证与未验事项见 [TASKS](V2.1.0_TASKS.md)；授权不延伸至 UI-04 或其他后续需求。

| 编号 | 候选改善 | 范围与约束 |
| --- | --- | --- |
| UI-01 | Mini 置顶按钮状态辨识 | 避免 Hover 覆盖已置顶外观，保留明确的选中状态；不改变实际置顶、隐藏或恢复行为。 |
| UI-02 | 设置校验反馈 | 去除字段与分组重复展示的同一错误，明确输入框与错误说明的关联；必要的首错定位在实施时确认，不在输入过程中抢焦点，不改变校验及保存规则。 |
| UI-03 | 设置提示文案 | 修正托盘、Mini“尚未开发”等过期说明及面向用户的开发流程措辞；按现有能力准确表达，继续明确年度包手动导入尚不支持。 |
| UI-05 | 普通设置按钮反馈 | 补充轻微 Hover / Active 反馈，保留主次按钮、键盘焦点和禁用辨识；优先使用现有样式，不新增动效库或复杂交互。 |

保持轻量 Windows 桌面工具定位：下班倒计时优先，保留现有主窗三卡、Mini 简洁结构、海蓝/珊瑚及亮暗主题和已确认猫鱼/浪花形象，不进行整体重新设计。

## 第二批：Dashboard 视觉打磨（2026-10-22）

用户另行授权主界面局部重设计，覆盖 Hero、工作进度及三张摘要卡。本节覆盖旧的 Dashboard 对齐、字号与三浪花排列约束，不扩大到 Mini、设置或其他功能。

- 采用统一中轴层级：主倒计时居中放大，状态、目标时间及提示围绕主数字组织；沿用系统字体和既有配色，以分组数字及较轻的分隔符突出时间。
- 进度使用清晰填充、单个原猫鱼节点及条中央百分比；移除固定三浪花阵列，不替换或删除源资源。保留既有状态、可见性及减少动画门控，不新增动画系统。
- 三卡采用统一居中排布，数字与单位为核心、日期及说明为次级信息；桌面宽度一排，极窄时换行。标题“在职自然日”改为“已工作”，仍使用原 `elapsedNaturalDays` 自然日口径，不改为出勤日或工时。
- 仅调整呈现组件及必要测试；倒计时、进度、发薪、休息日、估算和异常的数据含义与计算均不变。未验真实桌面观感，仍需用户人工体验。

## 暂缓与待确认

- **UI-04 暂缓**：Mini 次级文字和复合提示密度尚需实际体验依据；不能把待验证的拥挤或溢出风险写成已复现问题。
- 后续功能需求保持开放，由用户进一步确认后再补充范围与任务，不提前展开大量任务。
- [ROADMAP](../../ROADMAP.md) 中 F11-C 年度日历自动更新仍为待确认方向，**不是本轮已确定的开发任务**；本轮不设计或创建 GitHub Actions、联网服务及自动下载机制。F11-B 手动年度导入是否保留也未决定。

## 执行与验证边界

- 版本启动阶段仅建立分支与两份文档；第一批限于四项反馈改善，第二批限于上述 Dashboard 版式与信息表达优化，各自包含必要直接测试和版本记录。不修改业务计算、IPC、存储、配置格式、窗口管理与尺寸、版本号、依赖或源资源；不改写 V2.0.0 文档和 Tag，不合并 main。
- 后续 UI 任务优先复用现有组件与 tokens，保持倒计时、日历、IPC、配置格式、校验和草稿保护语义；不顺带重构后台服务。
- 验证与实际变更风险相称：执行类型检查、与变更直接相关的既有测试及隔离 Headless 检查，不重复 V2.0.0 完整验收，不启动 Electron，不进行生产构建或打包。测试专用组件 bundle 不作为发布产物。
- 涉及真实窗口显示、聚焦、托盘或多屏的 GUI 验证，须另列并取得用户对空闲时段的明确授权；未运行项目不得记为 PASS。
- V2.1.0 的完整范围和完成条件待后续需求确认；当前不得标记版本完成，不创建 V2.1.0 Tag 或 Release。
