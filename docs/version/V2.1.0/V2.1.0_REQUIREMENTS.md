| --- | --- | --- |

## 第二批：Dashboard 视觉打磨（2026-10-22）

用户另行授权主界面局部重设计，覆盖 Hero、工作进度及三张摘要卡。本节覆盖旧的 Dashboard 对齐、字号与三浪花排列约束，不扩大到 Mini、设置或其他功能。

- 采用统一中轴层级：主倒计时居中放大，状态、目标时间及提示围绕主数字组织；沿用系统字体和既有配色，以分组数字及较轻的分隔符突出时间。
- 进度使用清晰填充、单个原猫鱼节点及条中央百分比；移除固定三浪花阵列，不替换或删除源资源。保留既有状态、可见性及减少动画门控，不新增动画系统。
- 三卡采用统一居中排布，数字与单位为核心、日期及说明为次级信息；桌面宽度一排，极窄时换行。标题“在职自然日”改为“已工作”，仍使用原 `elapsedNaturalDays` 自然日口径，不改为出勤日或工时。
- 仅调整呈现组件及必要测试；倒计时、进度、发薪、休息日、估算和异常的数据含义与计算均不变。未验真实桌面观感，仍需用户人工体验。

## 第三批：Dashboard 三案探索（2026-10-22）

第二批已实现并通过定向检查，但用户不认可其视觉结果；不得将技术检查等同于用户验收。本批仅通过隔离预览生成三套完整 Dashboard 方案及截图，供用户选择后再授权正式落地。以下为本批最新展示约束，不直接替换正式界面：

- Hero、猫鱼进度、三卡必须作为完整方案共同探索，三案采用有明显差异的结构；倒计时为唯一核心视觉。
- 原猫 / GIF 与进度本体结合，百分比绑定轨道或滑块，不能放回右上角；本轮采用静态帧比较，不新增动画系统。
- 三卡标题均保留左上角，重组数字 / 单位 / 日期关系；统一为「下次预计发薪」「已工作」，已工作仍为自然日口径。
- 正式 App / Dashboard 暂不接入预览；不改业务逻辑、Mini、设置、后台、配置、窗口、依赖或版本号。允许最小预览支撑、类型检查、隔离 Headless 截图与检查，不进行真实桌面 GUI 测试。
- 交付 A「下班航线」、B「摸鱼水槽」、C「桌面时钟」的截图与说明；用户可选整案或混搭。本批不代替用户选择，不作为 V2.1.0 定稿或完成标记。

## Dashboard 选定方案正式落地（2026-10-22）

用户已确认 B「摸鱼水槽」的 Hero / 进度与 C「桌面时钟」的摘要卡组合，并授权接入正式 Dashboard。本节为当前有效设计决策，覆盖第二批对齐规则与第三批“仅预览、待择案”的阶段限制；历史方案保留作为记录，不再生成新方案。

- Hero 与水槽共用主视觉卡片，统一横向内边距和留白；使用 B 的轻字重大时钟、较轻分隔符及等宽数字，按容器及时长文本长度适配。状态置于右上，目标日期 / 时间及辅助文案居中；业务值与目标计算不变。
- 移除可见的「今日工作进度」标题，保留区域标签与原生 progress 语义。猫鱼使用原 GIF / 静态帧组件及原工作 / 加班、可见性、减少动画门控，随现有真实进度移动；百分比置于槽内、与猫纵向分离。水面按完整轨道取样并裁切，不随低进度压缩，不恢复固定三浪花。
- 摘要标题固定左上，左侧日期 / 说明，右侧数字 / 单位；三卡一致，长数字与窄容器按内容换行，不强行截断或维持固定高度。统一「下个休息日」「下次预计发薪」「已工作」；保留自然日口径、空值、零值、估算与异常说明。
- 复用现有 CountdownCard、FishProgress、MetricCard、tokens、素材和展示函数，不复制隔离预览作为第二套正式展示体系；未改业务计算、Mini、设置、IPC、后台、配置及窗口逻辑，未增加依赖或新的刷新服务。
- 仅保留现有 GIF / 小幅浮动及节点位置过渡；位置过渡使用 CSS transform、250ms ease-out 曲线，首次 / 恢复播放 / 缩放时仍不补播跳动。不新增水面循环或数字动画。实际动画舒适度待用户体验。

## 暂缓与待确认

- **UI-04 暂缓**：Mini 次级文字和复合提示密度尚需实际体验依据；不能把待验证的拥挤或溢出风险写成已复现问题。
- 后续功能需求保持开放，由用户进一步确认后再补充范围与任务，不提前展开大量任务。
- [ROADMAP](../../ROADMAP.md) 中 F11-C 年度日历自动更新仍为待确认方向，**不是本轮已确定的开发任务**；本轮不设计或创建 GitHub Actions、联网服务及自动下载机制。F11-B 手动年度导入是否保留也未决定。

## 执行与验证边界

- 版本启动阶段仅建立分支与两份文档；第一批限于四项反馈改善，第二批限于 Dashboard 版式优化，第三批限于三案隔离探索，选定方案落地限于上述 B / C 组合，各自包含必要直接测试和版本记录。不修改业务计算、IPC、存储、配置格式、窗口管理与尺寸、版本号、依赖或源资源；不改写 V2.0.0 文档和 Tag，不合并 main。
- 后续 UI 任务优先复用现有组件与 tokens，保持倒计时、日历、IPC、配置格式、校验和草稿保护语义；不顺带重构后台服务。
- 验证与实际变更风险相称：执行类型检查、与变更直接相关的既有测试及隔离 Headless 检查，不重复 V2.0.0 完整验收，不启动 Electron，不进行生产构建或打包。测试专用组件 bundle 不作为发布产物。
- 涉及真实窗口显示、聚焦、托盘或多屏的 GUI 验证，须另列并取得用户对空闲时段的明确授权；未运行项目不得记为 PASS。
- V2.1.0 的完整范围和完成条件待后续需求确认；当前不得标记版本完成，不创建 V2.1.0 Tag 或 Release。
