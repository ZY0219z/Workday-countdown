## 测试分层与取证

1. domain 单元测试：固定 clock/policies/calendar 输入，无 Electron/网络/真实当前日期，检查数学结果、状态、来源和错误；有必要的日期/区间不变量测试，避免仅复制实现。
2. main 服务测试：一次性用户目录、故障注入、写入队列/revision/备份；原源文件摘要前后对照。测试不得覆盖真实配置。
3. Windows Electron 集成：真实 Preload、IPC、两个窗口、tray、单实例和退出；既有 POC 安全与退出覆盖保留，应用不能在测试里关闭 sandbox。
4. UI 验收：固定时间截图，亮/深、不同窗宽/DPI、各种业务状态、键盘与减弱动画。
5. 真实 portable 验收：仅复制同一 EXE 到无开发环境的 Windows 标准用户机器，人工打开、断网、保存、重开、退出；记录 EXE SHA-256、OS build、硬件、账号权限和签名状态。

自动化只能使用本地测试 profile/调试参数；正式 EXE 正常启动不额外开放调试端口。退出检查包括 launcher、main、renderer、GPU/utility 进程及本次临时目录，不能只看页面消失。

### G05 建议预算与测量口径

参考机：Windows 11 x64、至少4逻辑核、8GiB RAM、SSD、标准用户；记录实际型号/电源模式/DPI。Win10若纳入也按相同场景实测。全部预算适用于本应用所有 main/renderer/GPU/utility/launcher，不能只测renderer。

- CPU百分比 = 所有进程 CPU秒增量 /（墙钟秒增量 × 逻辑核数）×100，按全机归一口径；预热30秒后连续采样120秒。建议平均：可见主窗/mini ≤2%，只有托盘 ≤0.5%。报告均值和P95，不把两个口径混用。
- 总 Private Working Set 建议：单一可见视图 ≤250 MiB、双窗可见（若Q08允许）≤350 MiB、tray-only ≤200 MiB。8小时每小时采样，末小时相对首个稳定小时增长≤20%，无单调泄漏趋势；重复切窗100次不积累renderer或订阅。
- 冷启动（进程不在运行，从SSD双击到可操作主窗）≤10秒；同实例恢复/切到主窗≤1秒；mini恢复≤1秒。分别测正常网络和真实断网，不预先解压为“冷启动”。
- 断电/关闭动画差异要记录；减少动画不只靠用户手动选项，隐藏和午休也应暂停。正式EXE体积初始建议≤120 MiB，超过须在实现前评审包内容与成本，不引入外置资源来规避单文件门槛。

## 验收记录模板

每次候选记录：版本/commit、EXE SHA与字节数、构建工具版本、主机OS/硬件/权限、是否干净/如何断网、case ID、步骤和预期、实际结果、状态、证据路径、失败原因/修复提交/重验。正式验收还记录所有Q最终选择和所有G判定。

输出目录可忽略，但最终发布记录必须把关键环境与结果写入版本文档。某台目标机不可获得时标记未验证，保留 G03/G04 未通过，不能用 POC 的受限PATH和Chromium offline替代。没有用户确认不得自动从规划进入实施或发布。
