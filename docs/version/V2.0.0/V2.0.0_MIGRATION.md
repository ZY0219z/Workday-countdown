## 具体问题证据与复现口径

1. 自然日：入职日和次日分别显示 0/1，即使两天之间包含休息日仍累加。新累计工作日不能复用 `work_days` 变量的当前语义。
2. 发薪顺延：按现有“非工作日延后”规则，2026-05-10（周日）应候选 05-11；旧 `today >= current_month_salary` 在 05-10 就选 06-10，跳过本期。若名义日 31，2026-01-31 延至 02-02；02-01 的代码只看二月，遗漏一月延来的候选。上述是在明确延后策略下的算法缺陷，不是替用户确定发薪制度。
3. 跨日加班：班次 2026-10-13 08:30–18:00 +600 分钟，目标为 10-14 04:00；到 10-14 00:01 旧版重新取当天开始，显示尚未上班并把昨日进度归零。新实现须锚定 10-13 班次。
4. 跨夜输入：旧版分别接受 22:00 / 06:00，但不创建次日结束；POC 明确拒绝。正式跨夜必须按 Q03 指定，并对可能和下一班重叠的加班按 Q04 校验。
5. 配置：根文件的 `overtime_minutes` 当前为 80，但没有班次日期；无法从文件时间或今天推断其归属。本轮保留原值和原文件，不执行迁移。
6. 动画：并行 after 链是源码级潜在风险，未证明当前 CPU 超标。新的低 CPU 承诺须通过正式性能测试，而非仅以框架变化推断。

### 预览、提交和回滚

1. 原生文件选择/有限来源探测后只读打开，限制 1 MiB；记录来源种类、摘要、解析错误。预览无配置写入副作用。
2. 每个已知字段单独校验，列出当前值、导入值、规范化和冲突；无效字段不可勾选，无日期加班需要独立选择。缺失字段保持当前正式值/已确认默认，不能变成 undefined。
3. main 生成短期 previewToken 绑定源摘要、当前 revision 和允许选择项。用户确认后重新核查源未变及 revision 未变；否则返回重新预览。
4. 备份当前有效配置和只读来源内容至正式用户目录，构造允许字段的新配置，原子保存。只有保存成功后记录 migration completed 和新 revision，再发布快照。
5. 同一来源摘要再次导入提示已处理；如用户确需重新覆盖必须再次预览确认，避免加班条目重复追加。用户取消或任何错误均不标记成功。
6. 恢复备份也需要预览和原子写入，保留正在替换的配置，不通过删旧目录或覆盖源文件“回滚”。未来 schema 只读拒绝降级写入。

正式V2迁移/导出/恢复须保留未被用户清除的历史加班设置，不能只导出活动班次或按日期清理。结构合法的历史条目即使当前工作周回算为休息，也可保留为不活动设置并注明原因，不据此生成班次；新增/应用到当前或未来无有效排班的加班则拒绝并要求跳过/修正。旧无日期值仍须用户选有效班次，不用“历史保留”绕过日期确认。

### 已确认的来源选择与合并边界（Q10）

有效正式配置始终作为预览基底；Python 与 POC 均作为可选来源，不自动彼此覆盖。若新用户同时发现两份，按来源分组让用户选时间，Python 可提供入职/发薪；只在明确确认后合并。window/theme 等旧源不存在的字段不会凭空从旧版推导。
