1. 每次受授权的开发回合先读本文件、REQUIREMENTS 中相关 Q、对应模块/迁移行和 TEST_PLAN 案例；核实当前分支、Git 状态和已完成任务。不能按旧 POC 的默认值猜业务规则。
2. Q01–Q12已确认，仍须检查当前D依赖及本回合实施授权。前置任务完成不自动授权后续；本轮D04由用户新指令明确授权，D05–D18仍不得开始。每个任务/迭代完成其验收就停止。
3. 每个任务只改列明模块和必要测试；保存旧 Python、配置和资源。不用 reset/clean 清理用户修改，不创建无关工程。推送仅在用户明确授权后检查远程祖先关系并普通推送，禁止强推、擅自合并或覆盖；本轮D04已有此授权。
4. 有意义的检查通过后记录实际结果、已知问题和状态，中文本地提交，检查工作区；生成 EXE 留忽略目录。不得新增提交二进制/缓存，也不移除历史跟踪产物。
5. 修改既有规则必须回到相应 Q 和所有受影响 T 案例。替换 POC 契约时可临时保留其有限适配，明确在 D11 移除；中间迭代不能交付启动即报错的页面，测试可更新协议但须保留原安全/保存/退出覆盖。升级依赖独立评审，不能把 audit 自动回退作为例行修复。
6. 未实现/未验证的项保持未完成；不存在“主页面做好所以完整重构完成”的判定。正式交付需所有 G 门槛通过。
