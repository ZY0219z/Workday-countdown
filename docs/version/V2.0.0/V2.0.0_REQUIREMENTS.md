## 已确认业务计算合同

以下合同落实已确认的 Q 决策；算法限额沿用规划基线，具体实现需后续授权和测试。Q 登记及详细条款是产品事实来源，不在其他文档保留相反默认值。

### 日期、在职与工作日

- 以日期字段计算自然日差，避免把毫秒差除以 24 小时当作跨日规则；本机夏令时、时区变化不得使相邻日期相差 0 或 2 天。
- 两项范围为 `[入职日, 今日)`：自然日 = `max(0, civilDay(今日)-civilDay(入职日))`；累计计划工作日计该范围内判定为工作日的日期。入职日当天均为 0，今天不进入计数。
- 允许未来入职日，两项均为 0 并提示“尚未入职”。历史按当前工作周、年度数据和用户覆盖回算，改变当前工作周会重算历史；不新增历史工作制分段。
- 日历优先级：用户日期覆盖 > 当年年度休假/补班数据 > 用户每周工作规则。冲突包拒绝导入；判定返回来源、年度核验状态及是否估算。
- 年度官方数据缺失时按周规则近似判断；用户已明确覆盖的日期采用该覆盖并注明自定义。累计计划工作日始终标识“按当前规则推算”，若范围内使用缺年回退还须标识“年度数据不完整”及涉及年份。
- 缺年回退的标记沿依赖链传递到下个工作/休息日、发薪调整、班次存在性及其进度/倒计时。自然日统计不依赖日历，不因缺年变为估算；明确班次的时钟差仍按实际时钟计算，但班次若由缺年周规则推算必须说明。不能把任何回退结果标记为官方已核验。
- 下个工作/休息日搜索必须有界；建议最多 366 天，无结果显示明确状态，不能无限循环。

### 班次、午休与倒计时

- 班次归属于开始日期 `shiftDate`，开始/结束和休息区间构建成明确的本地日期时间区间；不从字符串大小猜测是否跨夜。
- 支持同日及显式跨夜；同日结束晚于开始，跨夜结束归于次日，基础排班不超过 24 小时，不从相等时刻或字符串顺序自动开启跨夜。午休默认关闭，开启时区间在班内、不重叠，净工作时长大于 0。
- 上班前显示距离上班；工作中/午休/加班中显示到最终下班的墙上时钟剩余时间。午休期间倒计时继续减少，有效工作进度不推进。
- 明确状态：休息日、尚未上班、工作中、午休、加班中、已下班、配置/日历不完整。先解析有效班次，再判定状态；跨夜正在进行的班次不被“今日休息”覆盖。
- 秒数向上取整，结束时归零；每次依据当前时间重算，不能用每秒减一累计误差。跨日和休眠恢复重新解析仍有效班次，不按午夜硬清状态。

### 发薪日

- 名义每月 1–31 号，短月没有该日期则取当月最后一天；默认顺延下一工作日，用户可改提前到上一工作日或不调整，使用同一工作日历。
- 先计算每月基础日期，再按策略求实际日期；在包括前月的候选周期中寻找实际日期 `>= 今日` 的最近一次。建议覆盖过去12至未来12个名义月份，每次工作日调整最多366天，选择未来366天内最近的实际日期；无结果明确反馈。前月月底顺延到本月时不能遗漏；该有界算法也覆盖自定义长假导致的更早月份延迟。
- 实际发薪日当天显示“今天发薪 / 0 天”，次日才找下一期；不追踪实际到账，不按基础日提前跳期。提前策略也须考虑未来名义月份提前到当前月份的候选。
- 显示基础日期、推算日期和调整原因；日历不完整时标识预计。31 号、闰年二月、12 月跨年必须有独立案例。

### 加班、进度与清除

- 加班按 `shiftDate` 保存，0–600 分钟；跨午夜仍属原班，结束后不继承。历史保存的是加班设置，不是实际工作考勤，不按日期自动删除。
- 无有效排班的休息日不得凭空创建加班；独立休息日临时班次不纳入首发。新增/修改排班或加班不得造成无法解释的活动班次重叠，应拒绝候选修改并说明冲突。
- 手动清除仅清除目标 `shiftDate` 的加班设置，其他历史记录保持。有效性由当前时钟和班次区间判定，不用删除历史记录代替结束判断。
- 工作进度 = 已完成有效工作区间时长 / 全班有效时长；排除午休，包含当前班次已确认加班，夹紧到 0–100%，结束为 100%。无有效班次使用无进度/空值，不伪装为 0%。
- 修改加班、班次或休息区间后立即重算，允许真实进度倒退，小鱼始终反映新值；不增加独立正常/加班双轨进度。

### Q01 — 天数统计

保留入职以来的已过自然日，入职日显示 0；增加累计计划工作日。两项均不包含今天，按上述半开范围计算。工作日由日历、当前每周工作规则和用户覆盖推算；首发回算历史属于估算，不宣称实际出勤。允许未来入职日期，明确“尚未入职”，不出现负数。

### Q02 — 发薪规则

默认遇休息日顺延下一工作日，可改为提前或不调整；短月取当月最后一天。实际发薪日当天显示“今天发薪 / 0 天”。从包含前月的候选周期计算，修复基础日提前跳期。使用 Q06 日历，界面说明这是计划发薪日期，估算数据按依赖传播标记。

### Q03 — 排班与午休

支持同日和显式跨夜，以开始日期归属班次。午休可选、默认关闭，区间必须合法且属于班次。上班前距上班，工作中距最终下班；倒计时包含午休墙上时长，午休不计有效工作进度。跨夜班次用明确的结束日期，不能在午夜重新锚定到今天。

### Q04 — 加班规则

按班次日期保存 0–600 分钟；跨午夜仍归原班，结束不继承下一班。历史加班设置保留，不按日期自动删除。禁止无法解释的重叠活动班次；无有效排班的休息日不生成常规加班，独立休息日临时班次不纳入首发。清除只针对所选班次，其他历史不变。

### Q05 — 工作进度

按有效工作时长计算，排除午休、包含当前班次已确认加班，限制为 0–100%。排班、午休或加班变更后重算，允许倒退，小鱼反映最新值。无有效班次显示无进度而非 0%；不另设正常/加班双轨。

### Q06 — 离线工作日历

默认中国大陆、周一至周五工作。优先级是用户日期覆盖 > 年度休假/补班 > 每周规则；可手动指定某日工作/休息，不增加日期级自定义时间或独立临时班次。年度数据记录来源与版本；缺少官方年度数据时按周规则近似推算并醒目标注估算/不完整，影响范围按前述合同传播，不冒充官方核验。不联网自动抓取；D04 必须完成2024、2025官方数据核验。

### Q07 — 关闭和退出

主窗关闭默认隐藏到托盘，首次触发明确说明，可在设置中改关闭即退出。最小化保留其独立系统行为，不等同隐藏。托盘退出是真正退出；托盘初始化失败不能隐藏成无法恢复的进程，应保留可操作主窗或明确退出。

### Q08 — 迷你悬浮窗

默认不开启；用户主动开启后与主窗互斥显示，首发不实现共存模式。置顶由用户手动开关，不因开启迷你自动强制置顶；支持拖动、隐藏和托盘恢复。首次启动打开主窗，此后可恢复窗口位置；恢复位置不自动授予双窗显示或增加上次可见模式自动启动功能。切窗保留未保存草稿。

### Q09 — 外观主题与视觉审查

支持跟随系统、亮色、深色，以及海蓝和珊瑚；保留鱼和浪花。系统减少动画或应用减少动画任一启用就减少动画，两窗共用 token。正式 UI 开发前必须提供主窗、迷你窗视觉预览并获得用户审查确认；本轮只登记节点，不生成预览或实现 UI，旧 POC 截图/文本线框不等于该确认。

### Q10 — 配置迁移

支持 Python V1、Electron POC、正式 V2 导入及正式配置导出/恢复。可发现旧源，但不自动合并覆盖；先只读预览再用户确认。Python/POC并存时明确选字段；无日期旧加班不自动归今天，可跳过，或经单独明确选择有效班次日期后迁移，不能推断日期。保留源文件；成功前必须校验、备份、安全保存。

### Q11 — 平台与发布

Windows 11 x64 为首要验收目标；Windows 10 22H2 x64 仅实机通过后声明支持，未测/失败不冒称支持，也不以此替代 Win11 验收。唯一分发物是单个 Windows x64 Portable EXE，无Python/Node/手动依赖部署要求。未签名和 SmartScreen 风险明确说明并实测，不要求关闭防护。TEST_PLAN 原 G05 数值为已确认性能基线；不合理/无法测量须在开发前报告，不得失败后私自放宽。不自动推送或正式发布。

### Q12 — 时间与设置

使用系统本地时间与时区，休眠恢复、调时和跨日期后按实际时钟重算。设置显式保存/取消；主窗/迷你切换保留草稿，离开设置或真正退出时有未保存内容则提示保存、放弃、继续编辑。保存失败保留旧有效配置和草稿，不提示成功。主窗关闭到托盘是隐藏，不因隐藏丢弃草稿；关闭即退出和托盘退出则执行同一退出确认。
