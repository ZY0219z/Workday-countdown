## 产品定位与发布硬约束

面向个人的轻量 Windows 工作日倒计时工具，保留摸鱼主题。用户无需 Python、Node.js、管理员权限或手动配置资源；唯一分发物为 Windows x64 Portable EXE。允许自动解压到系统临时目录、在用户数据目录保存配置。核心功能须离线可用。

必须保留根目录 Python 旧版、原配置及资源，正式工程继续使用 `desktop/`。既定栈为 Vue 3 + TypeScript + Electron + electron-vite + electron-builder。不加入登录、数据库、后端、云同步、AI 对话、考勤采集或工资实际到账跟踪。

不纳入本次推荐的 V2.0 首发范围：自动更新、网络抓取日历、开机启动注册、全局快捷键、系统通知、打卡/休假审批、多公司/多人员档案、复杂粒子动画。以后若需要，应单独定义版本和验收。

## 业务计算合同草案

下面是推荐算法的约束和候选规则；涉及 Q 的选项仍未生效。

### 日期、在职与工作日

- 以日期字段计算自然日差，避免把毫秒差除以 24 小时当作跨日规则；本机夏令时、时区变化不得使相邻日期相差 0 或 2 天。
- 在职自然日和累计计划工作日分开。建议自然日用已过日差；累计日期范围 `[入职日, 今日)`，统计工作日历判定为工作的日期；当日纳入及工作制历史口径见 Q01。首发候选为按当前工作周、年度数据和用户覆盖回算，改变工作周会重算历史；不能说这是实际出勤。若需按历史工作制分段统计，须先补生效区间模型。
- 入职日在未来时不出现负数，应提示“尚未入职”，是否允许保存见 Q01。
- 推荐日历优先级：用户日期覆盖 > 当年官方休假/补班数据 > 用户每周工作日。冲突数据包拒绝导入；休息/工作判断返回来源和可信度。
- 对无年度数据的日期，是否允许以每周规则近似计算见 Q06。界面必须说明不完整，不能把推算值当成已核验值。
- 下个工作/休息日搜索必须有界；建议最多 366 天，无结果显示明确状态，不能无限循环。

### 班次、午休与倒计时

- 班次归属于开始日期 `shiftDate`，开始/结束和休息区间构建成明确的本地日期时间区间；不从字符串大小猜测是否跨夜。
- Q03 决定同日/跨午夜及午休范围。建议跨午夜用显式选项；同一班次不支持超过 24 小时的基础排班。休息区间必须在班内、不重叠，工作区间总时长须大于 0。
- 建议倒计时表示到最终下班的墙上时钟剩余时间，即午休期间也继续减少；进度则使用扣除休息的有效区间。两者含义必须在页面说明。
- 明确状态：休息日、尚未上班、工作中、午休、加班中、已下班、配置/日历不完整。先解析有效班次，再判定状态；跨夜正在进行的班次不被“今日休息”覆盖。
- 秒数建议向上取整，结束时归零；每次依据当前时间重算，不能用每秒减一累计误差。上班前显示距开工或距下班由 Q03 决定。

### 发薪日

- 名义每月 1–31 号。短月候选规则为取当月最后一天；非工作日候选为顺延到下一工作日，两项均由 Q02 确认，不是工具替用户确定公司的发薪制度。
- 先计算每月基础日期，再按策略求实际日期；在包括前月的候选周期中寻找实际日期 `>= 今日` 的最近一次。建议覆盖过去12至未来12个名义月份，每次工作日调整最多366天，选择未来366天内最近的实际日期；无结果明确反馈。前月月底顺延到本月时不能遗漏；该有界算法也覆盖自定义长假导致的更早月份延迟。
- 发薪实际日当天建议显示“今天发薪 / 0 天”，次日再转到下一期；不追踪实际是否到账。按基础日提前跳到下一期的旧版缺陷不应照搬。
- 显示基础日期、推算日期和调整原因；日历不完整时标识预计。31 号、闰年二月、12 月跨年必须有独立案例。

### 加班、进度与清除

- 建议每条加班设置绑定 `shiftDate`，保持旧版 0–600 分钟范围；是否允许超过下一班开始、休息日加班、如何限制冲突见 Q04。
- Q04 推荐结束前跨午夜仍属于原班，结束后不再对下一班生效；记录是否保留、何时清理由决策明确。绝不能仅在 00:00 擦除仍在进行的跨日加班。
- Q05 推荐工作进度 = 已完成有效工作区间时长 / 全班有效时长，包含经确认的加班区间，夹紧到 0–100%。休息段不推进，结束显示 100%；休息日无班次显示无进度。
- 修改排班/加班后允许业务进度重新计算，鱼的位置应与新值一致并提示已调整，不能人为保留错误的高值。是否把正常工作与加班进度分开见 Q05。
