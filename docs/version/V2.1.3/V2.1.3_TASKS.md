### 跨日加班校验修复及取消弹窗视觉优化

2026-11-24，基线 `a1de11391a1a`。原有预计结束时间、加班记录、Schema 和旧版导入均存在 600 分钟限制，班次查询仍按最长 34 小时估算。本轮在 `config-schema.ts` 中统一加班整分钟技术上限为 4319。该上限由现有时区适配器约束推导，所选时刻与正常结束时刻的民用时间差小于一天，两端时区偏移绝对值均小于一天，因此实际加班时长小于 72 小时。它仅是存储和解析的有限保护边界，界面仍只能选择正常下班日期或其次日的 `HH:mm`，没有增加多日选择能力。

`expected-end.ts` 继续按正常下班时间解释日期，晚于正常时刻使用同日，早于正常时刻使用次日，相等时保留原有规则，快捷弹窗提示无有效加班。实际分钟数沿用时区解析结果，DST 重复或缺失时刻仍拒绝自动选择。`overtime.ts`、Schema 2 和 `migration-service.ts` 共用上限，旧记录、零分钟记录和其他配置继续保留。`schedule.ts` 与 `config-validation.ts` 将邻班检查统一为前后各 6 个民用日期，并按各班次实际记录时长排除无关历史班次，防止扩大范围后已过期的 DST 缺失端点影响当前班次。原有常规班次时长和冲突判定保持不变。

`ipc.ts` 仅对已知加班字段的静态业务提示放行，并对超范围和过期班次使用受控提示，其他验证信息和内部异常继续脱敏。正常 14:15 下班时，选择次日 10:15 对应 1200 分钟。下一天正常上班且发生重叠时提示「加班时间与相邻工作班次重叠，请重新选择。」，下一天休息且无其他冲突时允许保存。失败保留弹窗与所选时间，配置和草稿不受失败输入污染，修改时间后可重试。

`OvertimeControl.vue` 仅调整取消正文，在浅蓝信息卡片中横向排列现有黄色月亮、弱化说明和加粗等宽时间，跨日日期紧凑显示在时间上方。询问区域使用 Flex 居中排列等长细线、现有时钟和原文案。弹窗保持 300 CSS px、自然高度、居中和等宽按钮，设置弹窗、悬浮时间面板、主界面开关及成功通知沿用现有实现。
