2026-11-09。基线为已发布 V2.1.1 及其后续首页文档更新，`main` 为 `9e9837a47877298af0eebb71c361260feffc8b33`。开发分支为 `codex/v2.1.2`。当前状态为 **候选构建与静态验证 PASS，Windows 人工验收 PENDING**。

## 范围

内置工作日历覆盖 2024–2027 年。2027 年度包包括 29 个安排休假日期和 5 个补班日期，逐项对照官方通知复核。沿用离线 JSON、可信清单和 `ordered-fields-v1` 摘要校验，年度更新随新 EXE 交付。2024–2026 年度数据文件与清单条目原样保留。[2027 年官方数据核验](D04_CALENDAR_VERIFICATION.md#year2027)

新配置默认启用 2027。读取已保存的 V2.1.1 或更早 V2 配置时，如果缺少 2027 的元数据，Main 从内置可信数据补入 2027 的启用项与摘要。以前手动启用了 2027 但缺少年度包的配置也能读取。已有年份的启用选择、工作时间、入职日期、发薪日、自定义日期覆盖和其他偏好保持原值。加载在内存完成，正常保存时沿用现有修订和备份流程。配置 Schema 继续使用 2。

兼容逻辑只处理修订号大于 0 的旧版已保存配置。首轮存储回归发现，修订号为 0 的恢复预览基底被补入新年度后会导致预览身份变化。收窄条件后，受影响的存储和运行时测试均通过。最终构建使用单独目录，首轮构建仅作中间记录。
